      How it works, and calling it from Postman or curl
      
    This page talks to the n8n workflow AI Prompt Generator — Multi-Model Evaluation
        through POST requests to its production webhook. A plain browser visit to that URL fails, because browsers send GET.
    
      
      
        
    1. A clarifier (Gemini) reads your goal and asks the 3 to 5 questions that would change the result most, with suggested answers ("mode": "clarify"; nothing is saved).
      2. 
        
    2. Your goal and answers become the creative brief. Three agents each draft a prompt from it: creative (Gemini), marketing (DeepSeek through OpenRouter), technical (GPT-OSS on Groq).
      3. 
        
    3. An evaluator (Gemini) compares them against the brief and keeps the winner word for word: version 1, Refined.
      4. 
        
    4. A refiner sharpens it: role, audience, constraints and output format spelled out. Version 2, More refined.
      5. 
        
    5. A second refiner makes that production-ready: context, steps, quality criteria, edge cases, an example. Version 3, Most refined.
      6. 
        
    6. The workflow answers with {"goal", "brief", "best_prompt", "choices": [{"level", "label", "prompt"} ×3]} and saves the goal and version 1 to Supabase.
      7. 
      
    
      
    Clarifying calls one model; generating calls six, on your own API keys. A request without mode generates straight from the goal, as before. The workflow must be published for the webhook to answer.
